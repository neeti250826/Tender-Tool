1. Overview and outputs

Goal: one common tender master covering the available records from 2023 onward for the TURMECA region, with every tender line traceable to its source, mapped to the Clearstate/Medtronic taxonomy (OU → Sub-OU → Product Category → Company → Family). Awarded and contracted records are the core market evidence; open tenders stay in the pipeline and out of realised value.

2. Analytical method aligned with ACEE

This version adapts the classification, evidence, valuation and quality checks in the ACEE tender analysis SOP (version 1.0, effective 9 September 2026). TURMECA retains its country-by-portal tabs and source-specific extraction rules. The CY2025 contract-duration method below is a TURMECA extension; the ACEE source does not prescribe duration proration.

  1. Fix the scope: use the approved OU, Sub-OU, Device Category, Company and Family combinations. Retain the taxonomy version and source Row ID, tender ID, item/lot and URL. Available source coverage is uneven; absence of an award is absence of collected evidence, not proof of no market.
  2. Screen broadly, classify at item level: multilingual words, product codes and titles produce candidates. The actual item narrative determines the category. Give integrated systems one primary category; exclude services, repair and incidental keyword matches unless explicitly in scope.
  3. Separate purchase evidence: final awarded or contracted product lines support award analysis. Open RFQs, preliminary evaluations, losing bids, cancelled awards and terminated contracts stay visible for review or pipeline reporting.
  4. Prevent duplicate counting: compare tender, buyer, supplier, item, quantity and dates. Retain a decision for reissues, superseded rounds and repeated contract values. Do not sum one multi-lot contract total on every lot. Without an evidenced allocation, item-level value remains blank.
  5. Map manufacturer evidence: supplier/distributor and manufacturer remain separate. Use explicit manufacturer/model evidence or a disclosed, defensible OEM-affiliate inference. Family names must be supported within the approved product-company combination. Unsupported manufacturer/family fields remain blank unless the taxonomy explicitly allows an Others category.
  6. Normalize quantity carefully: distinguish awarded units, requested units and framework maximums. Correct quantities only from an explicit narrative count and record the correction. Retain UOM; do not combine incompatible units or silently assume pack sizes. NUPCO equal-winner weights are an estimation convention, not evidence of actual call-offs.
  7. Keep evidence and estimates distinct: actual local award value, converted USD and reference-price estimates are separate measures. Preserve the existing FX date and method; a CY2025 assessment does not automatically imply 2025 FX. Annual-average and later spot FX in this release are disclosed limitations.
  8. Calculate comparable prices: grouped HBP = sum of attributable USD value divided by sum of the corresponding units, using only matched records with compatible UOM. Do not average row unit prices or include quantities whose value is unavailable. Installation, training, accessories and warranty can make a bundled HBP different from a device-only price.
  9. Make uncertainty visible: high confidence requires clear evidence, medium confidence a documented inference, and low confidence a review decision. Preserve unresolved rows and reasons outside core totals. Category mapping confidence and contract-period evidence are separate assessments.
Workbook convention: keep README, Summary, the seven data tabs and the portal-gap tabs. The existing green mapped headers are preserved. New assessment headers use purple to identify the added calculation block.

3. KSA — NUPCO nupco.com

Navigation

  1. Open https://www.nupco.com/tenders/tenders-list/ and pages /2/ … /5/ (the /en/ paths return 404). About 119 tenders are listed (NPT = open framework tenders, NDP = direct purchases).
  2. Open each tender page (nupco.com/tender/<slug>/). Read Tender ID, status (Available/New, Under Studying, Initial Results, Final Results, Cancelled), opening date and the document links.
  3. Download Tender Final Result PDFs (awards) and Tender Item List PDFs (requested quantities). 42 tenders have final results.
  4. Titles are Arabic; English titles were translated and stored in TURMECA_Tender_Master.xlsx > NUPCO_Tender_Families.

What the data contains

Final results: NUPCO item code (13 digits), item description, UOM, vendor (distributor), manufacturer, model/catalogue no., country, group. Several winners per item (framework). No prices or award values anywhere. Item lists give the requested (initial) quantity per NUPCO code.

Extraction

  1. parse_nupco_finals.py: reads each PDF table; aligns cells by each header's raw column span (merged cells shift columns), so no rows are dropped. Handles the collapsed one-cell header (NPT0043/25).
  2. parse_nupco_0033_25.py: NPT0033/25 (ENT) prints descriptions as overlapping text, so awards are read line by line (vendor no. 40xxxx … -Orig- manufacturer, country, catalogue) and descriptions come from the item list.
  3. parse_nupco_itemlists.py: quantities by NUPCO code; text-only lists are rebuilt by attaching wrapped lines to the nearest code row by position.
  4. build_ksa.py: joins quantity, maps each unique NUPCO code once, takes Company from the manufacturer, computes share of awards (1/n per winner) and estimated value. Award year = printed date on the final-result PDF.

Result: 67,632 award rows from 41 tenders (NPT0048/24 is a one-page Arabic notice with no awards).

Previous extraction

KSA_tender_awards_final.xlsx (13,480 rows, 50 tenders): only the 40 tenders not in this project's PDFs are added; it has supplier and quantity but no manufacturer, and its amount is one figure repeated per tender (not a price).

4. Turkey — EKAP ekapv2.kik.gov.tr

Navigation

  1. Start Edge with the debugging port, open https://ekapv2.kik.gov.tr/ekap/search and tick the Cloudflare box when it appears.
  2. node ekap_session.js or the Edge window must stay open. Scripts call EKAP's own API from inside the tab:
    • List: POST /b_ihalearama/api/Ihale/GetListByParameters with okasBransKodList (OKAS/CPV code), tender-date range, max 50 rows per page.
    • Detail: POST /b_ihalearama/api/IhaleDetay/GetByIhaleIdIhaleDetay with ihaleId.
    • Each call carries EKAP's encrypted headers (built in ekap_lib.js).
  3. node ekap_extract_medtech.js runs tier by tier (Core → Partial → Catch-all OKAS codes from EKAP_Product_Class), lists first then details; resumable.
Rate limit: about one call every 30 seconds (HTTP 429 otherwise; run with EKAP_PACE_MS=31000). If the check lapses (HTTP 428) the extractor waits until a person re-ticks Cloudflare. The full pull takes 40–50 hours; it was stopped after the core tier.

What the data contains

Per contract: winning supplier (distributor), contract date, contract value (TRY), approximate cost, highest/lowest bid; lots (kısım) with lot names; item-level OKAS codes; buying authority and city. No item quantities, no manufacturer. One contract value can cover many lots.

Extraction and previous data

build_turkey.py reads every detail JSON (this pull + the earlier IVD pull cache) → one row per contract × lot; year = contract date. The QC-corrected Turkey_EKAP_Contracts_Ending_2024_2026_EN_Corrected.xlsx covers the same contracts and is used to enrich rows (corrected English, quantity/UOM where given, low/high bids) and to map 673 extra lots.

5. Pakistan — Khyber Pakhtunkhwa and Federal

KP Health Department / DGHS healthkp.gov.pk dghskp.gov.pk

  1. With the VPN on, open https://healthkp.gov.pk/news/tenders (≈545 PDF links). Filter links for "Bid Evaluation Report", "BER", "Comparative Statement".
  2. Open http://www.dghskp.gov.pk/tenders.html — use http (the https handshake fails on Windows). It holds the FY2023-24 Govt MCC BER.
  3. Download: Govt MCC BERs FY2023-24, 2024-25, 2026-27 and the FY2025-26 draft comparative statement (text); DGHS "Selection and Rate Contracting of Medical Equipment…" BERs FY2024-25 to 2026-27.

Data: per bid — firm, item (generic name/size or "Model:/Make:"), unit rate PKR, lowest rate, scores; winner = highest total score. No quantities. MCC item numbers are re-used for different items across years — never join years by item number.

Scripts: parse_kp_mcc.py (reads numbers from the right of each row), parse_kp_ber.py (two layouts), build_pakistan.py.

Federal PPRA epms.ppra.gov.pk

  1. https://epms.ppra.gov.pk/public/evaluations?page=N — 3,676 federal evaluations (74 pages); filter titles for medical keywords (99 found).
  2. Each detail page /public/evaluations/evaluation-details/EVL… links a report PDF (/pdf?file=…). Scans are OCR'd with Tesseract (orientation auto-detected).
  3. Contracts register /public/contracts (694 contracts, almost none medical). The legacy ppra.org.pk/contract_org.asp now redirects here; EPADS is login-only.

Scripts: epms_evaluations.py, dl_bers.py, ocr_bers.py, parse_federal.py.

6. Kuwait — CAPT capt.gov.kw

  1. In the debugging Edge, open https://capt.gov.kw/en/tenders/winning-bids/ (Cloudflare passes in a normal browser); accept the terms popup only with user approval.
  2. node capt_crawl.js requests, from inside the tab, /en/tenders/winning-bids/?meeting_date_from=YYYY-MM-DD&meeting_date_to=YYYY-MM-DD&form=date&page=N month by month (10 rows/page), plus item pop-ups for health awards.
  3. build_kuwait.py translates Arabic subjects and maps them.

Data: meeting date, tender no., subject (Arabic), organisation, winner, total KD. 808 awards 2024–Sep 2026; Ministry of Health awards are services/works, so no device rows map. Volume signal only.

7. UAE — Dubai eSupply esupply.dubai.gov.ae

  1. Open https://esupply.dubai.gov.ae/esop/guest/go/public/opportunity/past (no login).
  2. Filter Buyer Organisation contains "Health" (Dubai Academic Health Corporation, Dubai Health Authority) and Publication Date equal to one day, then search (page functions setListUserAct('OpportunityListManager','search') + xhrPostListForm).
  3. Export with list.si?export=xls. Export is capped at 2,000 rows and the list is sorted by closing date, so it is exported one publication day at a time (node esupply_daily.js Health 2024-01-01 2026-10-01 3).
  4. build_uae.py splits each opportunity's Description into item lines "n: [code] ITEM - qty UOM" and maps them.

Data: 7,972 RFQs, 23,401 item lines with requested quantity/UOM. No award, winner or price. Volume signal only.

10. How the data is mapped

  1. Taxonomy source: Mapping_Taxonomy.xlsx (Google Sheet 1drBXEp…, tab "Combined Manufacturer List_Late"). Every mapped value is an exact string from it.
  2. Device Category / Sub-OU / OU — from the line item text only (never the tender title). vocab_rules.py holds ~270 rules, each = (OU, Sub-OU, Product Category, include patterns, exclude patterns), in English, Turkish (folded to ASCII) and Arabic. First matching rule wins.
    • Order-independent rules handle "THING, FOR USE" wording (e.g. "PULSE GENERATOR, NON RECHARGEABLE, FOR DEEP BRAIN STIMULATION").
    • For NUPCO "<item> RELATED TO <parent unit>", the item part is matched first, then the full text.
    • Turkey: Turkish rules on the lot name first, then the English (QC-corrected if available, else machine translation).
    • Precision first: generic consumables (gloves, syringes, dressings), drugs, lab reagents and catch-all words stay unmapped.
  3. Company — from the manufacturer only, never the distributor: alias table (e.g. Covidien, Nellcor, Kyphon → Medtronic; Ethicon, DePuy Synthes, Biosense → Johnson & Johnson; St. Jude → Abbott), then exact taxonomy name, then strict fuzzy match (≥95). Turkey/KSA-previous: only when the supplier's own name is the OEM or its affiliate.
  4. Family Name: a taxonomy family of that Company + Product Category whose distinctive words all appear in the model/catalogue/description.
  5. Included / Review / Excluded: The extraction build uses mapped category, award year 2024–2026 and award/contract status (and excludes terminated EKAP contracts). Preserve that original decision for audit. CY2025 uses the separate assessment status and evidenced contract overlap, so supported carryover from 2023 or 2024 can qualify. Pipeline, losing bids and unresolved duplicates do not qualify for assessed award totals.
  6. Mapping QC: after each build, sample mapped rows per tab and check for false positives (examples fixed: dental burs vs neuro burs, nasal speculum vs debrider blade, "rod" inside "introducer", "eus" inside "reusable", company names like "Barrett Hodgson"). Check recall by listing unmapped lines where the manufacturer is Medtronic.

11. Valuation, prices and FX

  • KSA: no prices published. Est. Value USD = requested quantity × UOM factor (DOZEN = 12; box/pack/blank → no value) × reference unit price × 1/n (n = winners on the item). Reference prices = median winning unit rate per Device Category from KP Pakistan BERs (ref_prices.csv, 13 categories). Where no reference price exists: volume and share only. These are scenario estimates based on Pakistani reference prices; they are not disclosed Saudi prices or a proven lower bound.
  • Turkey: Value USD only for single-lot contracts; never split or sum a multi-lot contract value. Unit price only where a quantity is known.
  • Pakistan: KP unit prices (HBP USD); federal offers are line totals without quantity.
  • Kuwait, UAE: volume signals only — no value built.
  • Share: NUPCO frameworks are multi-award; share of awards = sum of 1/n weights per company.
  • FX (fx_annual_usd.json): TRY = ECB annual average by award year (2024: 32.86, 2025: 39.55, 2026: 45.75); SAR 3.75 and AED 3.6725 (pegs); KWD ≈ 0.307; PKR 276.98 (spot, 1 Oct 2026).

12. Calendar Year 2025 applicable period, volume and value

Assessment period: 1 January–31 December 2025, inclusive. Use the live TURMECA Google Sheet. The assessment block is appended to all seven data tabs; portal-gap tabs have no tender rows to assess. Existing extraction dates, metrics, mapping decisions and header colors are retained.

Inputs and calculations

FieldRule
Contract Start Date / Contract End DateUse evidenced contract validity dates, not award signature, publication, final-result date or a financial-year label. Turkey dates are matched from the QC-corrected extraction by notice, item and supplier, or the previous-only notice/item key. Conflicting or unavailable dates remain unresolved; source information is retained in Period Evidence / Source.
Contract Duration (months)Whole anchored calendar months from start through end inclusive, plus a fraction of the remaining anchored month. Invalid or incomplete periods produce no duration.
Active in CY2025?Yes when an evidenced interval overlaps 2025; No when it is outside. Unknown when the period is incomplete or invalid. An available start after 2025 or end before 2025 can establish No. This period flag alone does not establish eligible awarded purchasing.
CY2025 Applicable Start / EndLater of contract start and 1 January 2025; earlier of contract end and 31 December 2025. Blank when there is no overlap.
Applicable Duration CY2025 (months)Sum the covered fraction of each calendar month in 2025: covered days in that month divided by the days in that month. A full calendar year is exactly 12 months; July–December is exactly 6 months. Partial months are fractional.
CY2025 Applicable ShareNumber of overlapping days in CY2025 divided by the total inclusive contract days. Keep full calculation precision. This uses the whole contract as the denominator, not 12 months.
CY2025 Applicable VolumeEligible awarded item quantity × applicable share. Preserve the original UOM. Requested quantities and unallocated framework quantities are not presented as awarded volume. Missing quantities remain blank.
CY2025 Applicable Value (LCY) / USDEligible attributable award total × applicable share. A unit price without quantity is not a total. Multi-lot contract totals without allocation remain blank. LCY is only comparable within one currency; do not sum across countries.
CY2025 Estimated Value USDExisting reference-price estimated USD × applicable share, when both the period and assessment eligibility are supported. Never combine it with disclosed award USD as a single actual-value total.
CY2025 Assessment Status / Basis / CaveatSeparate period unknown, invalid dates, outside year, eligible pro rata, pipeline, losing bids, out of scope, low confidence and duplicate review. Explain quantity/value evidence and the uniform-time assumption.
Interpretation: time proration is a uniform allocation of the contract total over its validity period. It is an assessment estimate, not observed 2025 delivery, invoice, cash flow or consumption. Use evidenced 2025 deliveries or call-offs for realised purchasing when available. Do not spread a one-off equipment purchase over time merely because it has a warranty or contract end date; such cases require review.

Source limits and treatment

  • Turkey — EKAP: use supported validity dates from the corrected source. A signed contract date alone is not a validity start. Single-lot/line-attributable values may be prorated; repeated multi-lot totals may not.
  • KSA — NUPCO: final-result dates identify award events, not framework validity. A 90/120-day delivery period per call-off is not the overall framework term. With no confirmed term or call-off allocation, active period, months and applied metrics remain unknown or blank.
  • Pakistan — KP: a BER fiscal-year title is not proof of the signed rate-contract start/end. Do not assume July–June validity without evidence. Published unit rates without quantities cannot produce total volume or value.
  • Pakistan Federal and UAE eSupply: pipeline evaluations and RFQs do not establish final awarded purchasing. Requested quantities may be reported separately as demand signals, never as CY2025 awarded volume.
  • Kuwait: no mapped product rows in this release; the consistent headers do not imply covered award evidence.

Assessment checks

Reconcile source Row IDs before date enrichment. Check missing and conflicting periods, end before start, full-year overlap, partial months, contracts spanning years and no overlap. Confirm applicable share is between 0 and 1, months between 0 and 12, and applied metrics do not exceed eligible contract totals. Eligible summaries must disclose unassessable record counts; blank unknown values must not be described as zero market activity.

13. English translation

  • translate.py calls translate.googleapis.com/translate_a/single in batches and caches every result in translation_cache.sqlite; re-runs only translate new text.
  • add_translations.py adds an "(EN)" column after any column with Turkish/Arabic text; a procurement glossary is applied first ("KALEM" = item(s), "KISIM" = lot — the translator otherwise outputs "pen").
  • If Google returns HTTP 429 (rate limit), run fix_translations_from_cache.py (restores earlier cached translations) and tr_glossary_fix.py (offline glossary for remaining procurement words; brand names kept).
  • Turkish lot descriptions use the human-corrected English from the previous QC file where available.

14. Rebuild order

  1. Build reference prices with build_ref_prices.py.
  2. In the KSA module, run build_ksa.py.
  3. In the Turkey EKAP module, run build_turkey.py.
  4. In the Pakistan module, run build_pakistan.py, then run parse_federal.py in the Federal module.
  5. In the Kuwait and UAE modules, run build_kuwait.py and build_uae.py respectively.
  6. Assemble the project master with build_master_mapped.py, then add coverage notes with add_gap_notes.py.
  7. Add English translations with add_translations.py. If the translation service is rate-limited, run fix_translations_from_cache.py, then tr_glossary_fix.py.
Assessment refresh: the original rebuild commands recreate the extraction workbook. They do not preserve added live Google Sheet assessment columns. Reconcile stable Row IDs, carry forward validated contract-period inputs and their sources, then reapply and check assessment formulas before replacing a released sheet. Preserve the green mapped-header formatting.
After changing vocab_rules.py, rebuild every country file before the master so all tabs use the same rules. Fresh source pulls (EKAP, eSupply, CAPT) are resumable and only fetch what is missing.

15. QC checklist and known limitations

Checklist

Release checks extend the ACEE method: retain source traceability, check category/company/family combinations, reconcile totals to eligible lines, review duplicates and value attribution, validate quantity UOM and FX, and inspect all formula results and table formatting. Distinguish missing evidence from zero.

  1. Parse logs: NUPCO nupco_parse_log.csv has no "unaligned" rows on device tenders; award row totals ≈ expected (≈ 67–69k).
  2. EKAP lists: every list JSON files has list length = total (paging advances by rows received).
  3. Spot-check 30–40 mapped rows per tab for false positives; list unmapped Medtronic lines for recall gaps.
  4. Value sanity: largest Est. Value / Value USD categories have plausible unit prices and enough observations (n_obs).
  5. Master opens in Excel without repair; Summary counts match tab row counts. Check for REF, DIV/0, VALUE, NAME and NA formula errors, and reconcile each CY2025 summary to its assessment statuses.
  6. No untranslated Turkish procurement words left in "(EN)" columns.

Known limitations

  • EKAP pull incomplete (core tier done; partial and catch-all tiers pending) because of the ~2 calls/minute limit.
  • KSA values depend on 13 Pakistani reference prices (some with only 1–4 observations); tracheostomy tubes dominate.
  • Sindh, Punjab and Etimad not covered; Kuwait and UAE provide no device values.
  • Requested quantities (NUPCO item lists, eSupply) are not actual consumption; framework allocation between winners is unknown.
